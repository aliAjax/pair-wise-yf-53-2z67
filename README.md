# pair-wise-yf-53 开源项目发布列车准备和门禁控制台

## 源提示词摘要
维护者创建跨仓库发布，关联版本、负责人、阻断问题和待合并依赖，安排冻结时间与分批顺序。发布前检查依赖、阻断、超时确认和顺序冲突，支持冻结、降级、回滚准备状态及可追溯审计。

## 技术栈
React Router 7 框架模式 + TypeScript + Mantine + Redux Toolkit + RTK Query + React Hook Form + Zod + Lingui + dnd-kit。

## 已实现闭环
- 跨仓库发布列车、依赖门禁和阻断问题三类业务对象。
- 门禁确认、阻断关闭、发布冻结、回滚和恢复准备状态。
- 仓库顺序拖拽、表单校验、远端健康查询与审计历史。
- localStorage 持久化。

## 并发与一致性
- 每个发布列车带修订号（revision），任何落库修改都基于修订号做乐观锁（CAS）：远端修订号
  已变化时本次写入被整体拒绝，后保存者不会盖没先保存者确认的门禁和关闭的阻断。
- 冻结资格在渲染中由 `computeFreezeEligibility` 实时计算（门禁全部确认、阻断全部关闭、
  远端健康检查已返回且通过），任一项变化立即重算；远端检查没回来先挡住冻结。
- 标签页间通过 storage 事件同步：本地无在途修改时自动打补丁；检测到远端修订号更高时显示
  “已过期/冲突”横幅，要求刷新后再操作。
- 旧数据没有修订号：第一次打开时为每个列车补 `revision=1`、为旧审计补操作人字段，立即写回后照旧使用。
- 修改先乐观应用再逐条进入写入队列；写入失败只重试没写进去的条目（已写入的不重发），
  新建列车的重试幂等。
- 审计条目记录操作人（按标签页署名）和动作类型（freeze / rollback / resume 等）。
